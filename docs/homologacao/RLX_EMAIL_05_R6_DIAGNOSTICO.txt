API E ORDEM VERIFICADAS
O harness usa Fetch.getResponseBody com Fetch.requestPaused.requestId.
Network.getResponseBody não é usado. Network.requestId não substitui Fetch ID.
As pré-condições foram conferidas no protocolo instalado:
node_modules/devtools-protocol/json/browser_protocol.json.
Fetch.getResponseBody requer pausa no estágio Response e não deve concorrer
com uma operação que afete a requisição antes de receber o corpo.
Fetch.takeResponseBodyAsStream não permite continuar a resposta original sem
reconstruí-la; não foi adotado sem necessidade comprovada.
Nos casos aprovados: pausa -> getResponseBody -> inspeção em memória ->
Fetch.continueRequest -> browser recebe resposta completa.
Fetch.continueResponse e fulfillRequest não são comandos do fluxo atual.
